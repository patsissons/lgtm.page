# Agent working rules

## Stack

pnpm + TypeScript + React + Vite + Tailwind v4 + shadcn/ui, with a
Cloudflare Worker backend ("Workers with static assets" via
@cloudflare/vite-plugin, config in wrangler.jsonc). Tested with Vitest (unit:
`src/`, `worker/`, `shared/`) and Playwright (e2e: `e2e/`), linted with
ESLint, formatted with Prettier.

- TypeScript runs side-by-side per the official TS 7 guidance: `tsc` (and
  `pnpm typecheck`) is the native TS 7 compiler via the `@typescript/native`
  alias, while the `typescript` package is aliased to
  `@typescript/typescript6` because typescript-eslint requires the TS 6 API.
  Do not "simplify" this to a single `typescript` dependency. Drop the dual
  setup only once typescript-eslint supports TS 7 natively.
- TS 7 removed `baseUrl`; keep `paths` entries relative to the repo root.
- Three TypeScript projects: `tsconfig.app.json` (src + shared, DOM lib),
  `tsconfig.worker.json` (worker + shared, Workers runtime types from the
  generated `worker-configuration.d.ts`), `tsconfig.node.json` (configs,
  e2e, scripts, plus `shared/types.ts` for the e2e fixtures). `shared/` must
  stay runtime-agnostic: no DOM, no Workers globals.
- `worker-configuration.d.ts` is generated by `wrangler types` (gitignored);
  `pnpm typecheck` regenerates it. Rerun after editing `wrangler.jsonc`.
- Vitest runs with globals off; always import `describe`/`it`/`expect` from
  `vitest` in test files.
- `vitest.setup.ts` registers Testing Library `cleanup()` explicitly; do not
  remove it, or rendered components leak across tests.
- Add shadcn/ui components with `pnpm dlx shadcn@latest add <component>`.

## Workflow

After making changes from a prompt and BEFORE committing:

1. Author new tests covering the changes being made.
2. Update any documentation affected by the changes (README, this file).
3. Run `pnpm format-and-validate` and repair any regressions in-line. This
   includes the Playwright e2e suite; never skip it.

Commit in small, modular units (one logical change per commit).

## Product invariants

- **The registry is the only list of apps.** `shared/apps.ts` holds one
  entry per app, alphabetical by slug (the display order; `apps.test.ts`
  checks it). Apps can live on any domain. Card text and images come from each app's
  own Open Graph tags at request time; registry `title` / `description` /
  `image` are overrides for apps with poor tags, not the normal path.
  Adding an app is documented in the README; keep that section current.
- **One failing app never breaks the index.** `loadApps` returns a card for
  every entry (`status: "error"` when the fetch or parse failed) and the UI
  flags it; never let a fetch error reject the whole list.
- **Metadata parsing is pure.** `worker/meta.ts` is a small tag scanner over
  the whole document rather than `HTMLRewriter`, so it runs in Vitest
  outside workerd. It reads `<body>` too because Next.js streams its
  metadata there; the first non-empty value wins, so `<head>` takes
  precedence. New fields need a fallback order and a test in `meta.test.ts`.
- **Caching.** `/api/apps` is stored in `caches.default` with an
  `x-lgtm-fresh-until` timestamp; past it, the stale list is served and a
  refresh runs in `ctx.waitUntil`. Lists with a failed app go stale after a
  minute. Clients get `max-age=300`. The edge key and the URL `useApps`
  requests both carry `appsVersion` (a hash of the registry,
  `shared/apps.ts`), so a registry change misses every data center's cache
  and every browser's on deploy; never key either on a fixed URL.
  `caches.default` is per data center, so `?refresh` only resets one.
- **Cards are single links.** The title link is stretched over the card
  (`after:absolute after:inset-0`); any other link on a card (the repo icon)
  sits above it with `relative z-10`. Never nest anchors.
- E2e is hermetic: specs call `stubApps` (`e2e/fixtures.ts`) to serve
  `/api/apps` and every `*.lgtm.page` request from fixtures.
- **Light and dark themes.** The theme is the `dark` class on `<html>`;
  `index.css` defines light tokens on `:root` and dark ones on `.dark`, so
  every colour must come from a token (or a `dark:` variant). The page
  follows the system setting until the visitor uses the toggle, which is
  remembered in `localStorage` (`lgtm:theme`). An inline script in
  `index.html` applies the theme before first paint and mirrors
  `src/lib/theme.ts` (key, media query, theme-color values): change both
  together. `e2e/theme.spec.ts` checks the script works without the app.
- Mobile-friendly: page padding comes from the `safe-x` utility in
  `index.css`; `e2e/home.spec.ts` guards against horizontal scroll.
- **Free to operate.** Cloudflare free tier only.

## Gotchas

- `assets.run_worker_first` is `true` so the `www` redirect runs before
  asset serving; the Worker falls through to `env.ASSETS` for everything
  but `/api/*`.
- The Workers Cache API is a no-op on `workers.dev` and in PR previews, so
  those always fetch the apps live.
- `wrangler preview` (the PR preview workflow) fails unless `wrangler.jsonc`
  has a `previews` block; keep the empty `"previews": {}`.
- `tsc -b` build info (`node_modules/.tmp`) can go stale after tsconfig
  edits; delete it if typecheck results look wrong.
- `public/og.png` and `public/apple-touch-icon.png` are generated
  (`pnpm og`, `scripts/og/render.ts`); regenerate them instead of editing the
  PNGs. `scripts/` is typechecked under `tsconfig.node.json` with
  `allowImportingTsExtensions` because Node runs the scripts directly.
  The icon is screenshotted with `omitBackground` so the rounded corners of
  `public/favicon.svg` stay transparent.
- `vitest.setup.ts` replaces Node's method-less `localStorage` with an
  in-memory one (cleared after each test) and stubs `matchMedia` as a light
  system theme; tests that need another answer redefine `window.matchMedia`.
- lucide-react has no brand icons; the GitHub mark is
  `src/components/github-icon.tsx`.
